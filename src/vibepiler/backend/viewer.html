Parse: every file becomes a syntax tree

tree-sitter parsed each file into a concrete syntax tree. The adapter for its language then walked that tree once and recorded definitions, imports, call sites with their enclosing scope, references and entry-point hints. Click a file to see it in the graph.

Link: names resolved across files

Semantic analysis in the compiler sense: names, not meaning. Each module gets a binding table from its imports and definitions. Every call site and reference is then resolved through that table, the enclosing class, and module/class member lookup. Calls whose receiver type is unknown are not guessed; their member names are kept so the passes stay conservative. Meaning, what a function does, is tab 4: Concepts.

How to read this

  1. Top rows are entry points; arrows point at what they depend on. Big orbs are big modules.
  2. A red wedge in an orb is the share of that module's lines that could go. Grey and still is unreachable.
  3. Moving dots are import and call traffic. Double-click a module to open it; click anything for its findings.
  4. Start with Biggest wins below, or the elimination plan in report.md.
